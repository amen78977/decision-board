## الاختبار

**١. فحص بنيوي — بلا كلفة، يعمل في CI:**

```bash
bash scripts/validate.sh
```

يفحص البنية · صحة JSON · frontmatter الوكلاء الخمسة · تطابق الاسم مع اسم الملف · العناصر النائبة · **نشر القواعد الـ١٢ على المشتقات الثلاثة** · وتسريب أسماء الوكلاء في سطر `📋`.

**٢. فحص المخطط الرسمي:**

```bash
claude plugin validate ./ --strict
```

**٣. اختبار سلوكي ميكانيكي** (يتطلب تثبيت البلَغن وجلسة مصادَقة):

```bash
bash scripts/smoke.sh
```

يشغّل الحالات الأربع ويفحص ما يُحسم آلياً: غياب `📋` في المستوى ١ · وجوده في ٢ و٣ · حد الـ١٥ سطراً · غياب عبارات التمييع · عدم تسريب أسماء الوكلاء.

**٤. تقييم سلوكي بحَكَم نموذجي** — الأحكام التي لا تُحسم بـ grep (هل اعترض؟ هل جامل؟ هل افتعل؟). المعايير مكتوبة في `evals/*/graders/criteria.md`:

```bash
claude plugin eval ./ --judge-model sonnet --report evals/report.html
```

> `plugin eval` في الوصول المبكر وقد يكون محجوباً. المعايير مكتوبة بلغة طبيعية، فهي صالحة للمراجعة البشرية كما هي.

## إن لم تُستدعَ المهارة تلقائياً

> **منذ 0.4.0 لا ينبغي أن يحدث هذا.** البلَغن يشحن hook على `UserPromptSubmit` يكشف صياغة القرار ويحقن التذكير بنفسه. تحقّق أولاً أن الـ hook محمّل:
>
> ```bash
> claude plugin details decision-board   # يجب أن يظهر: Hooks (1) UserPromptSubmit
> ```
>
> إن ظهر `Hooks (0)` فأنت على إصدار أقدم — راجع «فخّ التحديث» أدناه. وما يلي يبقى مفيداً لضبط الأولوية عند تعارض حاد.

المهارات يستدعيها النموذج بناءً على وصفها. عاملان يمنعان الاستدعاء عملياً:

**١. صياغة خبرية لا استفهامية.** «سأترك وظيفتي غداً» ليست سؤالاً — ولا تحمل علامة استفهام. وصف المهارة يغطي الحالتين صراحةً منذ 0.3.1، فإن كنت على إصدار أقدم فحدّث:

```bash
claude plugin update decision-board
```

**٢. تعليمات شخصية تُوجّه القرارات إلى مسار آخر.** إن كان في `~/.claude/CLAUDE.md` جدول محفّزات يُحيل القرارات إلى مهارة أخرى، فهو يسبق وصف المهارة في المنافسة. أضف سطراً يجعل الطاولة المسار الافتراضي:

```markdown
## decision-board — كل قرار، افتراضياً
`decision-board@decision-board` (بلَغن مثبّت)

**استدعِ مهارة `decision-board` عند أي قرار** — سؤالاً كان («هل أفعل؟» · «أيهما أفضل؟» · «محتار»)
**أو إعلان نية** («سأترك وظيفتي» · «سأستثمر» · «سأؤجل» · «قررت» · «حسمتها» · «ناوي»).

**انطبق حتى لو كان القرار شخصياً أو مالياً أو مهنياً وخارج سياق البرمجة تماماً.**
«هذا ليس قرار برمجة» ليس عذراً للتخطّي — بل هو بالضبط ما وُجدت له.

**وانطبق حتى لو بدت الصياغة واثقة أو متحمسة أو محسومة** — الثقة مؤشر على الحاجة لا على انتفائها.

هي **المسار الافتراضي** للقرارات، وتُنهي المستوى ١ بردّ مباشر فلا تُكلّف شيئاً على التافه.
وما عداها من مهارات القرار لحالاته الخاصة المعلنة فقط.
```

**ضعه قبل أي قسم آخر يذكر القرارات** — الأسبق في الملف يفوز بالمحفّز.

> **مقاس بالتجربة:** على جهاز فيه موجّه شخصي يُحيل القرارات إلى مهارة أخرى، فشلت ٣ من ٤ حالات سلوكية، وكان الرد يقول حرفياً «هذا ليس قرار برمجة» أو يعرض تشغيل المهارة المنافسة. البنية كانت سليمة بالكامل — والمحفّز وحده هو ما سقط.

**للتحقق أن المهارة مثبّتة أصلاً:**

```bash
claude plugin details decision-board
```

يجب أن يظهر `Skills (2)` و`Agents (5)`.

> ⚠️ في وضع `claude -p` غير التفاعلي، **أوامر السلاش تُمرَّر كنص عادي ولا تُفعَّل**. لاختبار `/decide` استخدم جلسة تفاعلية، أو اطلب المهارة بالاسم في `-p`.

## فخّ التحديث — الكاش لا يتبع الإصدار

`claude plugin details` يقرأ بيانات الماركت‑بليس، **لا الملفات المحمّلة فعلاً**. فقد يعرض لك الإصدار الجديد بينما الكاش ما زال يحمل القديم — و`claude plugin update` قد يفشل بـ`Plugin not found` بلا أن يصحّح شيئاً.

**تحقّق مما هو محمّل فعلاً:**

```bash
ls ~/.claude/plugins/cache/decision-board/decision-board/
```

المجلد الظاهر هو الإصدار العامل. إن خالف ما تتوقعه، أعد التثبيت نظيفاً:

```bash
claude plugin uninstall decision-board
rm -rf ~/.claude/plugins/cache/decision-board
claude plugin marketplace remove decision-board
claude plugin marketplace add amen78977/decision-board
claude plugin install decision-board@decision-board
```

> كلّفنا هذا الفخ دورة اختبار كاملة: نتائج «فاشلة» كانت في الحقيقة تختبر وصفاً قديماً.
